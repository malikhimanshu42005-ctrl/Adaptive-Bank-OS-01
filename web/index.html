2PL PROTOCOL

Two-Phase Locking (2PL) & Strict Serializability

RIGOROUS 2PL ENFORCED
💡 What Two-Phase Locking (2PL) does in simple terms: A transaction must acquire all its account locks during the Growing Phase before it can execute. Under Strict 2PL, it holds all locks until the transaction is fully finished (Commit or Rollback), which guarantees no other transaction reads uncommitted data (no cascading aborts).

1. Phase 1: Growing Phase

Transactions acquire exclusive locks on all required accounts (from_account & to_account) in strictly ascending order. Once all locks are held, the transaction enters execution.

Transactions in Growing/Waiting: 0

2. Critical Execution Section

With all required locks safely held, the CPU executes burst cycles. No other transaction can read or write these accounts, eliminating dirty reads.

Transactions in Critical Section: 0

3. Phase 2: Shrinking Phase (Strict 2PL)

Under Strict 2PL, all exclusive write locks are held until transaction completion (COMMIT or ROLLBACK). Releasing locks occurs simultaneously at termination, preventing cascading aborts.

DEADLOCK CONTROL

Coffman's 4 Conditions & Mitigation Matrix

DEADLOCK FREEDOM PROVED
COFFMAN CONDITION BANKING OCCURRENCE ADAPTIVE BANK OS MITIGATION TECHNIQUE STATUS
1. Mutual Exclusion Two transfers cannot modify the same account balance concurrently. Enforced via account-level exclusive locks in LockManager table. ENFORCED
2. Hold and Wait Transaction holds lock on Acc A while waiting for lock on Acc B. ELIMINATED: Non-blocking try-locks. If Acc B unavailable, Acc A is immediately rolled back. ELIMINATED
